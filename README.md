# 🫧 AI 泡沫检测仪 · AI Bubble Monitor

**Live:** https://ourword-ai.github.io/ai-bubble-detector/

19 条红线实时监测 AI 基建泡沫。三级判定——**干柴**（宏观环境易燃度）、**火药**（金融结构脆弱度）、
**扳机**（引爆事件）——配倒计时、八维度速览、与 1847 铁路 / 2000 互联网的八阶段对照、
红线自审与证伪清单。每个数字都带日期与出处。**Not investment advice。**

## 结构

| 路径 | 是什么 |
| --- | --- |
| `index.html` | 面板本体（单文件、零依赖、原生 HTML/CSS/JS） |
| `data/auto.json` | 自动数据管线输出（GitHub Actions 定时写入） |
| `scripts/update_data.py` | 抓 FRED 序列的脚本（纯 stdlib） |
| `.github/workflows/update-data.yml` | 每个工作日运行，有变化才提交 |

| `monitor.html` | 旧地址重定向 |

## 数据怎么更新

1. **自动管线**：GitHub Actions 每个工作日抓 FRED（核心 PCE 同比 `PCEPILFE`、单 A 公司债
   OAS 参考 `BAMLC0A3CA`）写入 `data/auto.json`，页面加载时替换 `[data-auto=…]` 的显示值并在
   页首标注刷新日期；自动值与页内快照判定冲突时标 ⚠。**自动管线只改显示，不改判定。**
2. **定期研究更新（每周一 / 周四）**：按页内「手抄清单」回原始来源核对价格类数据、核查事件
   （评级 / 财报 / S-1 / 减值 / 清算等）、录入到期倒计时、依据充分时翻转红线判定或增设新红线。
3. 所有变更连同依据留痕在提交历史里——本仓库的 git log 就是这页的审计轨迹。

## 维护规则（编辑 index.html）

- **计数不要手改**：页首、总判定、点状图、层级标题由脚本从三个层级块（`.tier .ti[data-h]`）实时核算。
  改判定只改条目的 `data-h`（`1` 命中 / `0` 未中 / `d` 口径分歧），表格行状态芯片（`.st[data-s]`）同步改。
- **数字必须带日期与出处**；没有可靠来源就不改，宁可标「待核」。
- **红线阈值只接受三类依据**：市场惯例 / 机械后果 / 物理约束；禁止把线画在数据后面
  （干柴层的状态描述型条件按「出生即断」豁免）。新指标先进「候选」，有线才进表。
- 接入自动管线的两条（核心 PCE、单 A OAS 参考）不用手抄，快照值落后没关系，加载时会被覆盖。
- 倒计时行到期出现「录入结果」；日期在 `.tr2` 的 `data-due` / `data-tid` 上，录入只存访问者本地。
